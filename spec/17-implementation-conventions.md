# 17. Implementation conventions

These conventions apply to every implementation. Most of them point to the section that defines
the rule.

1. **Zero third-party code (P1).** No runtime dependency in any package manifest. The standard library
   is used only for operating-system and runtime access. Test-only tools and official vectors are
   allowed.
2. **Synchronous (P7).** No asynchronous API, initialization or download.
3. **CPU-specific code (P9).** Run-time detection, portable twins, a forced-portable switch;
   assembly generated by a program is checked in CI to equal the generator's output.
4. **Errors, not panics** on caller input ([6.2](06-api.md#62-inputs-and-outputs) item 5).
5. **Unsafe code.** Each language confines code that bypasses its safety checks to the modules its
   profile lists (Rust [23.2](profiles/rust.md#232-security-mechanics), Go 24.2, Zig 25.2, Python 27.2), each with a comment that states why it is
   sound.
6. **Secrets wiped** ([14.5](14-security.md#145-wiping)); **constant time** ([14.1](14-security.md#141-constant-time)).
7. **Repository files.** `LICENSE-APACHE`, `LICENSE-MIT` and `SECURITY.md` at the root, and the
   license files in every package directory. Vector provenance lives in the vector tools.
8. **Source and mirrors.** The five packages are developed in the repository `crypterial/crypto-pq`.
   The Go and Zig packages are also published as the mirror repositories `crypterial/crypto-pq-go`
   and `crypterial/crypto-pq-zig` ([20.4](20-versioning.md#204-release-process)).
