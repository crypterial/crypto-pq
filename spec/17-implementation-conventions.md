# 17. Implementation conventions

These conventions apply to the implementation. Most of them point to the section that defines the
rule.

1. **Zero third-party code (P1).** No runtime dependency in the package manifest. The standard library
   is used only for operating-system and runtime access. Test-only tools and official vectors are
   allowed.
2. **Synchronous (P7).** No asynchronous API, initialization or download.
3. **CPU-specific code (P9).** Run-time detection, portable twins, a forced-portable switch;
   assembly generated by a program is checked in CI to equal the generator's output.
4. **Errors, not panics** on caller input ([6.2](06-api.md#62-inputs-and-outputs) item 5).
5. **Unsafe code.** Code that bypasses the safety checks of the language is confined to the modules
   that the profile lists ([23.2](profiles/rust.md#232-security-mechanics) item 1), each with a comment that states why it is sound.
6. **Secrets wiped** ([14.5](14-security.md#145-wiping)); **constant time** ([14.1](14-security.md#141-constant-time)).
7. **Repository files.** `LICENSE-APACHE`, `LICENSE-MIT` and `SECURITY.md` at the root, and the
   license files in the package directory. Vector provenance lives in the vector tools.
8. **Repository.** The repository `crypterial/crypto-pq` holds this specification, the compliance
   suite ([19.2](19-conformance.md#192-compliance-suite)) and the Rust package, which is released from it ([20.4](20-versioning.md#204-release-process)).
