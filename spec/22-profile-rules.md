# 22. Profile rules

1. A profile applies Part I to a programming language. It adds requirements and fixes the language
   form of each item; it never relaxes Part I. Where a profile seems to contradict Part I, Part I
   governs and the profile is defective.
2. A profile has five parts: the public API idiom; security mechanics; performance mechanics; build,
   packaging and platforms; and the conformance checklist.
3. Part II holds one profile, for Rust, the language of the implementation (P5): Section [23](profiles/rust.md).
